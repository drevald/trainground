# ADR 001: Выбор брокера сообщений по сценарию

## Статус
Принято

## Контекст
Магазину нужна связь между сервисами (catalog, orders, inventory)
без жёсткой синхронной зависимости через REST.

## Решение
- **RabbitMQ** — для fire-and-forget синхронизации каталога между
  сервисами с заранее известным набором consumer'ов. Новый сервис
  при старте делает разовый REST pull полного состояния, дальше
  подписывается на будущие изменения.
- **Kafka** — для `order-events`. Ценность не в "разослать и забыть",
  а в возможности нескольким независимым consumer'ам (notification,
  analytics) читать поток с разной скоростью, и в наличии истории
  изменений заказа как аудита.

## Альтернативы, которые рассматривались и отклонены
- Kafka для всего — избыточна там, где не нужен replay/история
  (например, синхронизация каталога).
